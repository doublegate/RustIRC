Strict Rustdoc initially exposed two bare IRCv3 URLs and two unqualified DCC method links.

then succeeds. No warning suppressions were added.

The publication fixtures execute the actual workflow shell with an isolated fake GitHub CLI.
An absent release creates a draft, a draft can resume asset preparation, and publication is
last. An existing published release or a query/authentication failure exits without mutations.
These fixtures verify shell control flow, not GitHub service availability or real asset execution.

Shellcheck still reports pre-existing quoting/style findings in unrelated helper/configuration
steps; structural Actionlint succeeds, and the changed publication step has no Shellcheck finding.

## Ordered release gate and recovery

1. Merge the reviewed candidate only after all non-skipped candidate CI checks succeed.
2. Verify clean release tree, exact merged SHA, manifest/lock/VERSION consistency, no duplicate
   remote tag or release, and no new audit vulnerabilities before creating the annotated tag.
3. Push the annotated `v0.4.3` tag. Master Pipeline runs tests, audit, docs, coverage and the
   minimum-toolchain check, then builds Linux x86_64, Linux ARM64 and Windows x86_64 archives.
4. Publish only after all release prerequisite jobs succeed and the six assets pass checksum checks.
5. Download all six published assets, validate SHA256/archive contents, and smoke-test the
   native Linux executable version. Record real cross-platform execution limits explicitly.

If a tag run fails before publication, fix the underlying failure before retrying Master Pipeline
via workflow_dispatch on the existing tag. A draft can be resumed. A published release is immutable;
do not replace its binaries or reuse its version for a different commit. For user-facing startup,
rendering, authentication or transfer regressions, restore the previous executable/config backup
and ship the corrective change under a new version. Host firmware, power policy and excluded
projects are outside this release.
